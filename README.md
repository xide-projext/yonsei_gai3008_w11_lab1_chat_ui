## 할 일

| # | 내용 | 상태 |
|---|---|---|
| 1 | `ListView.builder` + `reverse: true` — 최신이 아래 | ✅ **완성됨** |
| 2 | 말풍선 2종 — 사용자 오른쪽 / AI 왼쪽 | ✅ 완료 |
| 3 | 입력창 `TextField` + 전송 버튼 | ✅ 완료 |
| 4 | 빈 상태 — "무엇이든 물어보세요" | ✅ 완료 |
| 5 | 키보드가 입력창을 가리지 않게 | ✅ 완료 |

전송 버튼 또는 키보드 전송으로 메시지를 보냅니다. 공백 메시지는 무시하며,
약 1.5초 동안 세 점의 타이핑 애니메이션을 표시한 뒤 모의 응답을 추가합니다.
공백 전송을 막고, 사용자 메시지와 응답 상태 변경 시 최신 대화로 이동합니다. 대기 중에도 새 메시지를 보낼 수 있습니다.
실제 AI API나 별도 패키지는 사용하지 않습니다.
`ChatPage(initialMessages: const [])`로 빈 상태를 확인할 수 있습니다.

## 로컬 규칙 기반 챗봇

**실제 AI가 아닙니다.** `lib/services/mock_chat_service.dart`에서 키워드와
질문 유형을 분류하고 미리 작성된 문장 중 하나를 선택합니다. 외부 API,
API Key, 백엔드, 유료 서비스, 새 패키지를 사용하지 않습니다.
응답은 기본적으로 한국어이며 대기 시간은 1.5초입니다.

| 주제/유형 | 인식 예시 |
|---|---|
| Flutter 설명 | “Flutter가 뭐야?”, “Flutter 설명해 줘”, “Flutter란?” |
| Dart | “Dart 예시를 보여줘”, “다트는 왜 필요해?” |
| 위젯 | “위젯이 뭐야?”, “위젯 어떻게 사용해?” |
| 애니메이션 | “애니메이션 예시”, “타이핑 점은 왜 필요해요?” |
| API | “API란?”, “API 사용 방법 알려줘” |
| 수업 | “오늘 뭐 배워?”, “수업 실습 예시를 보여줘” |
| 인사 | “안녕하세요”, “Hello!”, “你好！” |
| 영어·중국어 | “What is Flutter?”, “How to use widgets?”, “Dart是什么？”, “动画是什么？” |

설명·예시·방법·이유에 주제별로 여러 답변을 준비하고 직전과 다른 답변을
선택합니다. “Flutter가 뭐야?” 다음 “예시를 보여줘” 또는 “show me an example”을
보내면 Flutter 예시를 답합니다. “Dart是什么？” 다음 “举个例子”도 지원합니다.

기억하는 것은 **현재 화면에서 인식한 최근 주제 하나**뿐입니다. 인사는 주제를
유지하고, 새 주제는 기존 주제를 바꿉니다. 이해하지 못한 질문이나 여러 주제가
섞인 질문에는 재질문하고 주제를 초기화합니다. 앱 재시작 후 기억은 남지 않습니다.
자유로운 문맥 이해나 임의의 코드 생성은 지원하지 않으며, 준비된 규칙 밖의
질문은 더 구체적인 설명을 요청합니다. 버전·날씨·시험 일정 등 최신 정보는 조회하지 않습니다.

서비스 단위 테스트는 표현 변형, 질문 유형, 답변 변경, 주제 기억과 초기화,
다국어 질문, 모르는 질문 처리를 확인합니다.

## 완료 기준 (수업 중 통과)

- 말풍선이 **좌우로** 나뉜다
- 입력창이 화면 **아래**에 붙어 있다
- 목록이 비면 **빈 상태 문구**가 보인다
- 키보드가 올라와도 입력창이 **가려지지 않는다**

## 힌트

- `reverse: true`면 index 0이 **화면 맨 아래**다. 그래서 `_messages[length - 1 - i]`로 꺼낸다.
- 색은 `Theme.of(context).colorScheme`에서 꺼내면 다크 모드에서도 안전하다.
- `TextEditingController`는 `dispose()`에서 정리한다.
- `ListView`를 `Stack`으로 감싸면 빈 상태를 위에 겹칠 수 있다.

## 초기 화면과 오류·재시도 실습 (1.11)

앱은 예제 대화 없이 **무엇이든 물어보세요**로 시작합니다. 상단의
**대화 초기화** 버튼은 메시지, 입력값, 최근 주제와 대기 중인 작업을 모두 지웁니다.
일상·공부·음식·여행 주제도 지원합니다. “점심 메뉴 추천해 줘”, “공부 어떻게 해?”,
“여행 추천해 줘” 뒤 “예시를 보여줘”처럼 질문해 보세요. 준비된 로컬 문장만 사용하며
실제 AI 추론, HTTP 요청, 최신 정보 조회는 하지 않습니다.

오류 테스트 방법:

1. 상단 벌레 아이콘 **개발용 오류 시뮬레이션**에서 401, 429, 500, timeout을 선택합니다.
2. 표시된 개발용 안내를 확인하고 메시지를 보냅니다. 설정은 다음 메시지 한 번에만 적용됩니다.
3. 1.5초 뒤 해당 한국어 오류 말풍선과 **다시 시도** 버튼을 확인합니다.
   429는 첫 실패 뒤 1초 → 2초 대기로 자동 재시도를 두 번 수행한 후 오류를 확정합니다.
   기다리는 동안에도 입력과 새 메시지 전송이 가능합니다.
4. 오류 후 다른 메시지도 보내 보세요. 기존 오류의 **다시 시도**를 누르면 그 오류에
   연결된 사용자 입력을 처리합니다. 개발용 오류를 해제하고 1.5초 뒤 해당 말풍선을
   정상 응답으로 교체하며 사용자 메시지는 다시 추가하지 않습니다.
5. 오류를 선택했지만 보내기 전이라면 **일반 채팅 (오류 해제)**로 해제할 수 있습니다.
   초기화하거나 화면을 닫으면 타이머도 취소합니다.

`ChatError`와 `ChatReply`가 공통 오류/응답 상태를 관리하고 `AnimatedSwitcher`가
TypingDots 로딩 → 성공/오류를 전환합니다. 수동 재시도는 누른 오류에 연결된
메시지를 사용하므로, 여러 오류가 있어도 다른 질문을 잘못 재전송하지 않습니다.

`flutter test`는 각 오류 표시, 재시도 복구와 중복 방지, 오류 후 새 전송,
429 대기 간격·횟수 제한, 시뮬레이션 해제 및 초기화를 검사합니다.
